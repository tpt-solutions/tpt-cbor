Design Specification: tpt-cbor v1.0
1. Executive Summary
tpt-cbor is a pure-Rust, zero-dependency implementation of the CBOR (RFC 8949) data format. It is designed to serve as the foundational binary serialization substrate for the TPT pure-Rust stack.
Unlike existing implementations that rely on the serde ecosystem or carry transitive dependencies, tpt-cbor is built entirely on core and alloc. It prioritizes deterministic encoding, zero-copy decoding, panic-free execution, and a simplified parsing state machine to enable future formal verification.
2. Core Design Principles
Absolute Zero Dependencies: The core crate has zero external dependencies. No serde, no log, no hashbrown. It relies exclusively on core, alloc, and optionally std (behind a feature flag for I/O).
Strict Canonicalization: While it can decode standard CBOR, it strictly encodes to a deterministic, canonical subset. Identical data structures will always produce identical byte streams.
Panic-Free & Bounded: The parser will never panic on malformed input. Recursion is strictly bounded to prevent stack overflows and simplify verification.
Zero-Copy First: Decoding borrows directly from the input slice. No intermediate allocations are made for strings, byte arrays, or map keys.
3. Dependency & Feature Policy
To maintain the "no dependencies" rule, the crate is structured with strict feature gates:
default: Enables alloc. Provides the heap-backed Value type, Vec/String codecs, and to_vec.
std: Enables std::io::Read and std::io::Write streaming support. Implies alloc. (Still zero external dependencies).
no_std: Built with default-features = false. Operates in #![no_std] using only core, with no allocator. Only borrowed and scalar decoding is available in this mode (Value, Vec, String and [T; N] decoding are not).
derive: Opt-in. Adds the tpt-cbor-derive proc-macro crate and its build-time syn/quote dependencies. The default build stays dependency-free.
Ecosystem Bridge: Integration with serde or other ecosystems is explicitly excluded from this crate. If needed, a separate tpt-cbor-serde bridge crate will be authored, keeping the core pure.
4. Wire Format Specification (Strict Canonical CBOR)
tpt-cbor implements RFC 8949 but enforces a Strict Canonical Subset for encoding to eliminate ambiguity and simplify the parser:
Definite Lengths Only: Indefinite-length strings, byte arrays, arrays, and maps are rejected during decoding and never emitted during encoding. This eliminates complex state-machine transitions.
Minimal Integer Encoding: Integers are always encoded in the minimum number of bytes required (e.g., 1 is encoded as 0x01, not 0x18 0x01).
Strict Map Ordering: Map keys must be sorted by the bytewise lexicographic order of their encoded form, as specified in RFC 8949 §4.2.1. A key whose encoding is a prefix of another sorts first. Duplicate keys are rejected. (Amended from the earlier length-first rule to match RFC 8949 §4.2.1.)
Float Canonicalization: NaN payloads are normalized to a single canonical quiet NaN (0xf97e00). Floats are encoded in the smallest representation that preserves the value (e.g., 1.0 is encoded as a half-precision float, not double).
Unsupported items: Tags, undefined (0xf7), and unassigned simple values are rejected in both strict and lenient mode. Lenient mode only relaxes the canonical-form rules above (minimal integers, float width, map order, duplicate keys). Indefinite lengths are always rejected.
5. Core API Architecture
Because we cannot rely on serde, tpt-cbor provides its own lightweight, zero-cost traits.
5.1. The Encode and Decode Traits
// Core traits defined in tpt-cbor
pub trait Encode {
    fn encode(&self, encoder: &mut Encoder<'_>) -> Result<(), EncodeError>;
}

pub trait Decode<'a>: Sized {
    fn decode(decoder: &mut Decoder<'a>) -> Result<Self, DecodeError>;
}

5.2. Zero-Copy Decoder
The Decoder holds a reference to the input slice and tracks the current offset. It returns borrowed data for strings and bytes.
pub struct Decoder<'a> {
    input: &'a [u8],
    offset: usize,
    depth: usize, // Bounded recursion tracker (checked against max_depth; see §6)
    config: Config, // strict (default) or lenient
}

impl<'a> Decoder<'a> {
    /// Returns a borrowed string slice directly from the input.
    pub fn decode_str(&mut self) -> Result<&'a str, DecodeError> { ... }
    
    /// Returns a borrowed byte slice directly from the input.
    pub fn decode_bytes(&mut self) -> Result<&'a [u8], DecodeError> { ... }
}

5.3. Dynamic Value Type
For schemaless use cases, a lightweight Value enum is provided. It uses alloc::vec::Vec only when explicitly requested by the user (feature alloc). Integers are limited to i64; out-of-range integers, tags, undefined and unassigned simple values are DecodeErrors. Maps are stored as a Vec of pairs. Encoding sorts them and rejects duplicate keys.
pub enum Value<'a> {
    Integer(i64),
    Bytes(&'a [u8]),
    Text(&'a str),
    Array(Vec<Value<'a>>),
    Map(Vec<(Value<'a>, Value<'a>)>), // Sorted into canonical order on encode; strict decode requires canonical order
    Float(f64),
    Bool(bool),
    Null,
}

6. Safety and Verification Strategy
To ensure the library can be formally verified (e.g., via Kani or future agentic verification tools), the internal architecture is restricted:
Bounded Recursion: The Decoder enforces a maximum nesting depth (default: 64, hard ceiling 256 regardless of configuration). If the depth exceeds the limit, it returns a DepthExceeded error. This guarantees the call stack cannot overflow. The encoder enforces the same default limit, so its output is always decodable.
Bounded Containers: A declared array or map length must fit in the remaining input (otherwise UnexpectedEof). It must also not exceed Config::max_items (default 2^20 per container), otherwise LimitExceeded. Pre-allocation is capped at 1024 slots, so a header cannot force a large buffer before its elements are read. The max_items limit applies to each container, not to the document as a whole.
Checked Arithmetic: All offset additions and length calculations use .checked_add() and .ok_or(DecodeError::Overflow). No unwrap() or expect() is used on arithmetic operations.
Flat State Machine: Because indefinite-length items are banned, the parser does not need a complex stack to track nested indefinite contexts. The state machine remains flat and highly predictable.
No Unsafe Code in Core: The core crate is #![forbid(unsafe_code)] and is 100% safe Rust. No unsafe code is planned for v1.0. Any future SIMD path would be an optional, isolated feature with its own unsafe audit (see todo.md, Later).
7. Performance Characteristics
Bitwise Header Parsing: The major type and additional information are extracted with shifts and masks. No branch-free guarantee is claimed; performance claims require benchmarks.
UTF-8 Validation: Uses core::str::from_utf8. SIMD is not used in v1.0. An optional simd feature is deferred until benchmarks justify it (see todo.md, Later).
Zero Allocation on Decode: Decoding borrowed and scalar types (&str, &[u8], integers, floats, bool, Option and tuples of these) does not allocate, and neither does skip_item validation. Derived structs and enums allocate only if they hold a String, Vec, Value or [T; N] field, because those decode types allocate. Structs built only from borrowed and scalar fields decode with no heap allocation.
8. Implementation Roadmap
Phase 1: Core Substrate: Implement Encoder, Decoder, Encode, Decode traits, and the Value enum. Enforce strict canonical encoding. (Zero dependencies).
Phase 2: Derive Macros: Create a separate tpt-cbor-derive crate (which will depend on syn/quote) to auto-generate Encode/Decode implementations for structs and enums.
Phase 3: Formal Proof: Write kani proofs for the core parser to mathematically prove the absence of panics, out-of-bounds reads, and unbounded recursion.
Phase 4: Ecosystem Bridge: (Optional) Build tpt-cbor-serde to allow downstream users to use serde derives if they refuse to adopt the native tpt-cbor traits.
